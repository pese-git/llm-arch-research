Задача: $ARGUMENTS

Ты — оркестратор: код сам не пишешь, передаёшь контекст субагентам и следишь за процессом. Правила — `CLAUDE.md` и `docs/dev/`.

0. **Ветка.** `git branch --show-current`. Одна задача — одна ветка от актуального `master` с префиксом типа (`fix/`, `feat/`, `refactor/`, `perf/`, `test/`, `docs/`, `chore/`). Если ты на `master` или ветка отстаёт — скажи пользователю и предложи команду; без согласия ветки не создавай.

1. **research-architect** — передай задачу (issue — через `gh issue view`). Результат: ADR, фаза плана или пункт бэклога, источники и задачи `[model]`, `[training]`, `[verify]`, `[notebook]`, `[docs]` с критериями готовности.
   **Стоп:** покажи пользователю кратко решение, источники, меняется ли результат моделей или формат чекпоинтов (несовместимость), список задач. Дальше — только после одобрения. Для мелкого исправления без альтернатив этот шаг можно сократить до списка задач.

2. **Реализация** в порядке зависимостей:
   - `[model]` → **model-engineer**; `[training]` → **training-engineer** (тесты пишут они же, сначала красные);
   - `[verify]` → **verification-engineer** — сверка с эталоном и доказательство, что регрессия падает на старом коде (когда исполнители закончили и никто не правит файлы).

3. Если менялся результат модели, API библиотеки, глава с Mermaid или конфиги экспериментов — **notebook-engineer**: перестроить рисунки, обновить схемы, прогнать затронутые ноутбуки.

4. **docs-author** — `[docs]`: руководство, глава, `llm/README.md`, CHANGELOG, бэклог/план со статусом. Числа берёт из запусков исполнителей.

5. **check-runner** — по затронутым путям. FAIL → исполнителю зоны, повтор.

6. **paper-reviewer** (если затронуты формулы, архитектуры, обучение или главы) и **code-reviewer** — параллельно.

7. CHANGES REQUESTED / ISSUES FOUND → раздай BLOCKER, MAJOR, P1, P2 исполнителям, затем шаги 5–6. Максимум 3 итерации; если блокеры остаются — остановись и покажи их пользователю.

8. **Итог пользователю:** что сделано; несовместимость (да/нет, что в CHANGELOG); таблица проверок; таблица «регрессия падает на старом коде»; вердикты; черновики сообщения коммита (английский, Conventional Commits) и описания PR на русском («Проблема», «Что сделано», «Несовместимость», «Проверка»).

Без явной просьбы: не делать `git commit`/`push`, не открывать PR, не запускать бенчмарк (~35 минут) и долгое обучение.
